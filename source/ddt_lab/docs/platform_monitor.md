# Platform 每 3000 轮自动评估

本机监测服务：`ddt-platform-monitor.service`（systemd user service）。当前训练及机器人来源以
`logs/launches/rear_clearance_latest.json` 为准；机器人为 `ddt_ros2_control` 的 `compress_v1`。

**当前已按用户要求停止训练和评估，并禁用后台监测。** 最新保存模型为
[`model_8200.pt`](../../../checkpoints/d1_platform_rear_clearance/README.md)。代码的上台课程已改为 30 cm 起步，
但尚未按新课程续训，30/40 cm 新协议的成对基线也尚未完成。

## 检查与判断

- 总轮数 3000、6000、9000、12000、15000、18000 检查；20000 轮最终评估后结束，不增加训练预算。
- 代码当前协议为 `platform-monitor-v2-30plus`。再次启用前必须用同一个 checkpoint 完成 30/40 cm 成对评估，
  初始化匹配协议的基线和源码指纹。每次改善后更新参考模型；未改善时保留此前参考。
  旧 20/30 cm 的结果和决策保留在历史记录中，不参与当前比较。
- 上台课程高度范围为 0.30–1.00 m，共 40 级。第 0 级随机高度约 30–31.75 cm；初始等级沿用 0–5 级，
  对应约 30–40.5 cm。下台课程及其他地形使用各自的原有范围。
- 固定 30 cm、40 cm 上升台阶，每种高度 64 个回合、seed 42、20 秒、0.4 m/s 前进指令。
  保留启动和 reset 随机化，关闭推扰和观测噪声，使用确定性策略均值。
  地形粗糙度按新高度范围对应的难度生成，因此重新建立基线，不能与旧协议直接比较。
- 优先比较无碰墙干净通过率：到达台顶、两后轮各至少一次干净落台、全回合无后轮碰墙标志、
  无失败终止、侧偏不超过 1 m。几何到顶率单独记录，不等同干净通过率。
- 碰墙沿用 reward 的几何与净接触力估计，不是接触对真值。干净落台比例按每后轮每次锁定目标的落台事件计数，
  不是回合成功率；粗糙表面可能在一个实际台阶内产生多次目标。

任一种高度的普通通过率或干净通过率下降超过 5 个百分点，均不判为改善。
满足此前提时，两高度平均干净通过率提升至少 5 个百分点，或碰墙时长减少至少 15% 且干净落台比例不下降超过
2 个百分点，或干净落台比例提升至少 5 个百分点且碰墙时长增加不超过 5%，判为改善。
两高度干净通过率均达到 95% 时保持设置。这些是实用效果门槛，不是统计显著性检验。

## 自动调整范围

用户希望 reward 尽量简单。当前规则只调整两个已有权重，不添加 reward 项、不改变碰墙和净空判定：

| 参数 | 初值 | 自动范围 |
| --- | --- | --- |
| `approach_penalty_scale` 提前避墙惩罚 | 2.0 | 0.5–6.0 |
| `clearance_bonus` 抬轮进展奖励 | 0.25 | 0.25–1.0 |

移动能力明显下降时，接近惩罚乘 0.8、抬轮奖励乘 1.25；大部分首碰尚未离地时，分别乘 1.35 和 1.25；
无碰墙但缺少提前净空的落台较多时，只将抬轮奖励乘 1.3；其余停滞情况两权重乘 1.2。
到边界后保持训练并在报告标记需分析，不继续叠加奖励。结构性调整需要依据新轨迹另行设计；后台服务执行的是这些明确规则。

调参前检查源码一致性、checkpoint/优化器有限性并运行测试。保留模型、日志、源码快照和调参原因，
从当时最新的完整 checkpoint 续训，恢复优化器。进程未正常启动时尝试一次旧权重恢复。
因为按 checkpoint 恢复，最多会重做不足一个保存间隔（通常 100 轮）的更新；仿真和各环境课程等级重新初始化。
评估在训练同时运行；评估失败或数据不完整时不改训练，记录错误并重试。
源码被手动修改时暂停自动比较和调参，避免判定口径变化。手动停止训练后不会主动复活该进程。

## 查看与控制

```bash
systemctl --user status ddt-platform-monitor.service
journalctl --user -u ddt-platform-monitor.service -n 30
# 只停止监测，不停止训练（本次已另外停止训练进程）
systemctl --user stop ddt-platform-monitor.service
# 仅在完成新协议基线初始化且决定重新训练后启动
systemctl --user start ddt-platform-monitor.service
```

本机和用户服务需要持续运行。状态、下一检查轮数及历史在 `logs/monitor/platform/state.json`；最新报告在
`logs/monitor/platform/latest_report.md`；各次完整数据在 `baseline/` 和 `iteration_NNNNNN/`。
TensorBoard 原实验下的 `auto_monitor_30plus` run 提供 `AutoEval/30cm/*`、`AutoEval/40cm/*`。
旧 `auto_monitor` run 保留作为历史。未完成的新协议评估保存在 `baseline_30plus_008100/`。
监测结束后不会向聊天窗口主动发消息，结果保存在这些文件和 TensorBoard 中。

最后完整评估为旧协议第 6000 轮。第 8100 轮的新协议补测只完成了 30 cm，40 cm 补测已随停训中止；
这些结果不能作为新协议的完整基线。
调整课程下限不增加 reward 项，也不引入按高度开启或关闭 reward 的额外分支。
